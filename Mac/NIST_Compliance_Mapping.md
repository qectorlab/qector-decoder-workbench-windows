# QECTOR Decoder Workbench: NIST & FIPS Compliance Mapping

This document details the compliance architecture and security controls implemented in the QECTOR Decoder Workbench v1.0.1. It aligns the application's capabilities with the requirements of NIST SP 800-171, NIST SP 800-53, and FIPS 140-3 for secure, air-gapped, and enterprise-connected deployments.

## 1. Access Control (AC) / Information Flow Control
*NIST SP 800-53: AC-3, AC-4 | NIST SP 800-171: 3.1.1, 3.1.2*

*   **EgressGuard (Air-Gap Isolation):** When `QECTOR_AIRGAP=1` is set, or when running as a frozen executable, the `compliance.py` module hooks the Python socket, HTTP, and SSL interfaces. It dynamically blocks all non-loopback connections (e.g., preventing data exfiltration to 0.0.0.0 or external IPs) and raises a `QectorEgressBlockedError`.
*   **Entra ID Role-Based Access Control (RBAC):** For connected enterprise environments, `entra_auth.py` evaluates Microsoft Entra ID `roles` claims (e.g., `Qector.Viewer`, `Qector.Operator`, `Qector.Researcher`, `Qector.Admin`) to gate access to benchmarking, exporting, and administrative features.

## 2. Audit and Accountability (AU)
*NIST SP 800-53: AU-2, AU-6 | NIST SP 800-171: 3.3.1, 3.3.2*

*   **Structured SIEM Auditing:** Blocked network egress attempts, authentication events, and administrative actions are logged in a structured JSON Lines format (`logs/egress.jsonl` and `logs/audit.jsonl`). These logs include the caller timestamp, thread ID, target address, calling module, and full stack trace for immediate ingestion into enterprise SIEMs.

## 3. Identification and Authentication (IA)
*NIST SP 800-53: IA-2, IA-5 | NIST SP 800-171: 3.5.1, 3.5.2, 3.5.3*

*   **Multi-Flow Authentication:** The suite supports device code flow, interactive PKCE loopback, WAM/Windows Broker SSO, and Service Principal client credentials, integrating natively with enterprise IdPs via MSAL.
*   **Offline Token Vouchers:** Staging environments can issue offline, cryptographically signed vouchers that allow air-gapped instances to assert identity without external network connectivity.

## 4. System and Communications Protection (SC) / Cryptography
*NIST SP 800-53: SC-7, SC-13, SC-28 | NIST SP 800-171: 3.13.1, 3.13.8, 3.13.11*

*   **FIPS 140-3 Alignment:** Cryptographic operations are restricted to SHA-256 / SHA-384 / SHA-512 for hashing and AES-256-GCM / PBKDF2 (with >600,000 iterations) for key derivation and data at rest encryption.
*   **Native OS Token Caching:** Token persistence avoids plaintext storage by integrating with OS-native secure enclaves: DPAPI (CryptProtectData) on Windows, SecretService on Linux, and Keychain Services on macOS.
*   **Anti-Tamper Monotonic Clock:** `utils.enforce_monotonic_clock()` writes an encrypted watermark of the last execution time. If the system clock is rolled back by more than 24 hours, the application raises a `QectorSecurityError` and degrades to a safe verification mode to prevent offline time-bomb circumvention.

## 5. Software Integrity and Provenance (SI)
*NIST SP 800-53: SI-7 | NIST SP 800-171: 3.14.1*

*   **Zero-Egress AST Attestation:** The startup routine performs a static AST scan of the codebase to guarantee that no unauthorized telemetry, auto-updaters, or network libraries are imported outside of the explicit loopback/Entra ID paths.
*   **Hermetic Asset Bundling:** All documentation, fonts (DejaVu Sans), and graphical assets are bundled locally. Generated reports (HTML, PDF, Markdown) use Base64-encoded SVG/PNG images and inline CSS, ensuring no external CDN or web font requests are made.
